# D06 — 원본 로그의 UTF-8 읽기 오류

2026-09-26. **사용자가 승인한 A안으로 23쌍 모두 준비를 완료했다.** `rca_log_encoding.py`의 손실 없는 읽기 어댑터를 별도 시도로 적용했다. [인공 검사 10개](evidence/rca_log_encoding_tests_20260926T064939884092Z.json)와 [실물 23쌍 결과](evidence/rca_log_recovery_20260926T071852891429Z.json)를 보존한다. 기존 정상 403쌍을 합쳐 426쌍 전부 준비됐으며 실제 모델 생성/RCA는 아직 실행하지 않았다.

실물 검사에서 읽은 CSV 값에 포함된 오류 바이트 1,484,835개를 그대로 보존했다. 이벤트 식별/선택 열은 유효했고 최종 원본 선택 프롬프트의 오류 바이트는 모두 0개였다. 복구 worker의 최대 RSS는 0.989GiB였다. 원본·최초 실패를 유지했고 행/Pod 제외나 문자 삭제/대체는 하지 않았다. 이는 승인한 로컬 읽기 조건의 성공이며 저자 조건 동일성은 계속 UNCONFIRMED다.

## 실제 실패와 근거

전체 426쌍의 기본 읽기를 마쳤다. [최초 전체 목록](evidence/rca_prompt_preparation_20260926T071419543832Z.json): 성공 403쌍, UTF-8 실패 23쌍(PR 20211203 7, PR 20220606 3, CC 20231207 13). 다른 종류의 읽기 실패는 없었다. 실패 쌍도 모두 실험 대상에 유지하고 승인된 A안을 순차 적용한다.

PR 20211203의 `cluster-version-operator-7767956c46-p4p9c_messages_structured.csv`를 원본 함수가 읽다가 `UnicodeDecodeError`로 실패했다. 629,181,681바이트 파일의 SHA256은 기존 배포 원본 기록과 일치한다. 첫 오류는 바이트 위치 8,057의 `0xc3`다. 파일 전체에서 UTF-8로 해석할 수 없는 바이트 12,944개를 확인했다. 다운로드 이후 로컬 파일 변조나 LLM 응답 파싱 오류라는 근거는 없다.

[진단 증거](evidence/rca_log_encoding_20260926T063257723849Z.json): 진단 목적으로만 손실 없이 읽은 결과 1,949,527행이었다. 공식 `generate_log_prompt`가 선택한 72,660문자에는 오류 바이트가 **0개**였다. 이 진단 프롬프트는 실제 입력으로 저장하거나 모델에 전달하지 않았다. 원본 함수는 각 템플릿에 대응하는 일부 예시를 선택하므로, 파일 전체의 읽기 실패와 최종 선택된 예시의 문자 오류 여부는 다를 수 있다.

## 채택한 A — 오류를 보존해 읽고, 선택 결과가 정상일 때만 허용

승인받은 다음 범위에서만 로컬 읽기 어댑터를 적용하고 검증한다.

1. 원본 소스·CSV·실패 디렉터리를 보존한다. 정상 파일에는 기존 기본 UTF-8 읽기를 유지한다.
2. 원본 해시가 일치하고 엄격한 UTF-8 읽기에서 실제로 실패한 파일만 `encoding_errors="surrogateescape"`로 읽는다. 모든 행을 그대로 읽으며 바이트 삭제·대체문자 삽입·인코딩 추측을 하지 않는다.
3. 이 방식은 잘못된 바이트를 특별한 내부 문자로 보존한다. 원래 바이트로 되돌릴 수 있으나, 글자의 본래 의미를 복원하는 방식은 아니다. [Python 3.11 오류 처리 정의](https://docs.python.org/3.11/library/codecs.html#error-handlers), [설치 계열 pandas read_csv](https://pandas.pydata.org/pandas-docs/version/2.2/reference/api/pandas.read_csv.html).
4. 원본 이벤트 식별·선택에 사용하는 열의 문자 유효성을 검사하고, 원본 함수를 그대로 실행한다. 선택된 최종 프롬프트에 오류 바이트가 없고 엄격한 UTF-8 인코딩에 성공할 때만 준비본으로 채택한다. 이벤트 식별 열이나 최종 프롬프트에 오류가 남으면 중단한다.
5. 파일별 해시·오류·행 수·검사 결과·어댑터 적용 여부를 기록한다. 조건을 충족하지 못한 파일을 제외하거나 임의 수정하지 않는다. 실제 입력 준비는 별도 시도로 저장하여 기존 실패를 덮어쓰지 않는다.

현재 첫 파일의 관찰상, 원본이 선택한 유효한 문자열을 바꾸지 않고 읽기 실패만 해소할 가능성이 있다. 모든 파일의 성공이나 저자와 같은 결과는 보장할 수 없다. 저자의 실제 인코딩 처리 방식은 공개 자료에서 확인하지 못했으므로 **원본 대비 읽기 조건 차이 / 저자 동일성 UNCONFIRMED**로 명시한다.

## 대안 B — 현재 엄격한 읽기 유지

실패를 보존하고 저자의 깨끗한 로그 또는 실제 인코딩/전처리 코드를 기다린다. 다른 독립 준비 검사는 진행할 수 있지만, 해당 로그가 필수인 사례의 실제 실행은 막힌다. 문제 파일이나 Pod를 제외하는 것은 이 대안에 포함하지 않는다.
