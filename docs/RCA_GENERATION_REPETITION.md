## 권장안 A — 로그 요약의 반복 억제 설정만 분리 검증

사용자 승인 후 단일 검증을 통과했다. 실패 요청을 별도 진단으로 한 번 실행할 때 `presence_penalty`만 `0.0 → 1.5`로 바꾼다. 같은 토큰을 다시 생성하는 경향을 낮추려는 변경이며, 단일 요청에서 반복 해소를 확인했지만 전체 응답의 내용 정확성은 보증하지 않는다.

| 항목 | 변경안 |
|---|---|
| 적용 범위 | 로그 요약 전용 별도 프로필 |
| 바꾸는 값 | presence_penalty 0.0 → 1.5 |
| 유지 | 모델/양자화, non-thinking, 원본 입력·프롬프트, seed 42, 원본 로그 온도 0.5, top_p 0.95, top_k 20, min_p 0, 출력 8,192, 문맥 81,920, GPU all/FP16, timeout 300초 |
| 첫 검증 | 실패했던 동일 요청 1건; 자동 재시도·추가 수치 탐색 없음 |
| 확인 | 정상 종료, 반복 목록 해소, 제공된 로그가 없다는 모순의 해소, 기존 요청 형식과 근거 유지 여부 |
| 성공 후 | 사용자 승인 범위에 따라 새 프로필로 두 사례 전체 로그 요약을 통일하여 생성하고 통합 검증 계속 |
| 기존 결과 | 148건과 실패 원문 모두 이전 프로필 기록으로 보존. 다른 설정의 결과를 하나의 균일한 실행으로 섞지 않음 |
| 적용하지 않는 단계 | RAG 최종 합성·인과관계 판단·RE·PC/RWR의 기존 설정은 유지 |

[Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-4B#best-practices)는 non-thinking 일반 작업에 presence_penalty 1.5를 포함한 설정을 제시하고, 0~2 범위 조정이 끝없는 반복을 줄일 수 있다고 설명한다. 높은 값의 언어 혼합·성능 저하 가능성도 명시한다. 위 A안은 변경 범위를 줄이기 위해 이 값만 검증하는 제안이며, 공식 권장 설정 전체를 적용하는 것은 아니다. MATMCD 저자의 설정도 아니다. 양자화 모델·고정 llama.cpp에서의 효과는 실제 확인이 필요하다.

샘플링 변경은 생성 내용과 후속 RCA 순위에 영향을 줄 수 있다. 따라서 단순 파싱/경로 수정으로 취급하지 않으며 승인된 D07 차이로 기록했다. 실패 한 건의 성공은 모든 입력의 안정성이나 의미 정확성을 보증하지 않는다.
