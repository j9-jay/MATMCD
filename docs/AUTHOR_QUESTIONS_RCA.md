**현재 발송 검토 문안은 [최종5개 질문의 국문·영문 메일](AUTHOR_INQUIRY_RCA_SHORT.md)이다.** 사용자 지정 순서인 기존1→6→4→3→2만 남겼다. 이23개 목록은 근거·답변 대조용으로 보존하며, 이번 메일에서 제외한 항목을 확인 완료로 처리하지 않는다.

기준 소스는 `D2I-Group/matmcd@ef2c3ecad0f5ddb9c3d20a8523c2c1043d213190`, 논문은 제공받은 arXiv `2412.13667v2`다. 공개 소스의 동작과 저자가 표4를 얻은 실제 실행 조건을 구분한다. 여기서 “미확인”은 조사한 논문·고정 소스·공개 자료로 실제 조건을 확정하지 못했다는 뜻이며, 저자가 해당 조건을 사용하지 않았다는 뜻은 아니다.

## 3. 항목별 질문·현재 선택·필요 자료

### Q01. 표4의 정확한 데이터와 최종 CSV

- **미확인:** 표4의 PR/CC 순위가 어느 날짜·장애 사례·배포본·최종 CSV에서 나왔는지 확정할 수 없다. 공개 진입점 기본값은 PR 20210517이며, Figure5 예시 시각만으로 실제 평가 날짜를 정할 수도 없다.
- **현재 선택:** 배포 revision을 고정해 임시 CSV를 생성했다. PR 20211203 준비본은 218 Pod·51,529행, CC 20231207은 196 Pod·79,252행이다. 논문은 PR 216 Pod·131,329 길이 / CC 168 Pod·109,351 길이를 기재한다. 이 차이를 같은 원본의 단순 부분 비율로 해석하지 않는다.
- **질문/요청:** “표4에 실제 사용한 날짜·장애 ID, 다운로드 revision/파일 해시, 최종 CSV와 열 설명·타임스탬프·후보 목록을 제공해 주실 수 있습니까? 논문의 Pod 수와 길이는 전처리 전/후 어느 단계의 값입니까?”
- **중요성/근거:** 입력부터 달라지면 PC와 모든 후속 결과가 달라진다. [재현 명세](REPRODUCTION_SPEC.md), [전처리 결과](PROVISIONAL_RCA_PREPROCESSING_RESULT.md), [고정 출처](../configs/upstream.json).

### Q02. 6/7개 메트릭을 Pod 한 변수로 만드는 방법

- **미확인:** 최종 RCA 로더는 Pod별 열을 읽지만, 여러 메트릭을 이 열로 변환하는 MATMCD 전처리 코드가 확인되지 않았다.
- **현재 선택:** Pod별 가용 비상수 채널을 각각 z-score(`ddof=0`)로 바꾸고 동일 가중 평균한다. 통계량은 정렬된 전체 행에서 계산한다. 이 방식은 저자 사용 근거가 없는 주요 로컬 가정이다.
- **질문/요청:** “메트릭을 선택했습니까, 평균/가중합/차원축소했습니까, 아니면 Pod×metric을 별도 변수로 사용했습니까? 정확한 수식·메트릭 목록·가중치·정규화 코드와 학습 구간을 제공해 주십시오.”
- **중요성/근거:** 변수 간 상관·조건부 독립성을 직접 바꿀 수 있다. [전처리 명세 P-05](PROVISIONAL_RCA_PREPROCESSING.md), [설정 metric_fusion](../configs/rca_preprocessing_proposal.json).

### Q03. 시간 정렬·장애 관측 구간·분할

- **미확인:** 시각 정렬, 리샘플링/평균, 관측 시작·종료, 장애 전후 구간, 정규화와 EVT 초기화 구간이 명확하지 않다. 별도 train/validation/test split도 확인되지 않는다.
- **현재 선택:** 선택 메트릭의 정확한 타임스탬프 교집합 전체를 사용하고 보간·추가 시간 집계는 하지 않았다. PR 20211203에서 CPU 22,982행 등 교집합 밖 관측은 제외됐다. 준비 CSV 전체를 썼다는 사실이 배포 원자료의 모든 행을 썼다는 뜻은 아니다.
- **질문/요청:** “어떤 시간 해상도·타임존·구간을 썼고, 미정렬/중복/결측 시각은 어떻게 처리했습니까? 정상 보정 구간과 장애 평가 구간을 나눴습니까? 정규화는 어느 구간에서 fit했습니까?”
- **중요성/근거:** 장애 신호의 비중과 정상 분포 추정이 달라진다. [전처리 명세](PROVISIONAL_RCA_PREPROCESSING.md), [상세 결과 §3.2](RCA_ORACLE30_RESULT_REPORT_20260927.md).

### Q04. EVT의 정확한 구현과 후보 제거 기준

- **미확인:** 논문은 EVT로 무관한 Pod를 제거한다고 설명하지만 MATMCD용 선택 코드·임계값·최종 Pod 목록이 없다.
- **현재 선택:** LEMMA 참고 DSpot 동작과 `d=10, q=0.0001, n_init=100, level=0.95`, 양쪽 tail·alert·bounded 활성화, `max_excess=200`을 사용했다. 공통 시간축의 첫100개가 정상 구간인지는 검증되지 않았다. 초기화 이후 어느 비상수 메트릭에서든 양수 점수가 한 번 있으면 Pod를 유지한다. 그 결과 PR218/CC196개가 모두 남았다. 이후의 정답 포함30개 선택은 별도 개발 조건이다.
- **질문/요청:** “EVT/SPOT의 구현·버전·파라미터·입력 해상도·정상 초기화 구간, 이상 판정과 Pod 유지/제거 조건은 무엇입니까? score 크기/비율/지속시간/상위N 기준이나 기간 제한을 사용했습니까?”
- **중요성/근거:** 최종 후보 집합과 원인 전파 경로를 결정한다. 참고 코드의 값은 MATMCD 저자값으로 간주할 수 없다. [설정 evt](../configs/rca_preprocessing_proposal.json), [전처리 결과](PROVISIONAL_RCA_PREPROCESSING_RESULT.md).

### Q05. Pod 목록·메트릭 누락·상수 채널·KPI 정의

- **미확인:** 인프라 Pod 포함 여부, 합집합/교집합 선택, 누락 메트릭과 상수 채널 처리, KPI의 실제 대상·정규화·그래프 역할이 확정되지 않았다. CC IOPS는 배포 자료에서5개 Pod만 존재하고 공통 구간에서 상수다.
- **현재 선택:** 메트릭별 Pod 합집합, 누락 채널 0 채우기 없음, 표준편차가 정확히0인 채널은 제외, 이름순 열 배치다. 배포 KPI 값을 바꾸지 않고 마지막 `Latency` 열에 놓았으며 KPI도 그래프/방향쌍에 포함했다.
- **질문/요청:** “최종 Pod·서비스·메트릭 매핑과 선택 규칙, 누락/상수 처리, KPI의 정확한 요청·단위·집계·위치를 알려 주십시오. KPI는 원인 후보인가, RWR 시작용 관측 노드인가요?”
- **중요성/근거:** 이름순은 동점 순위와 첫 질문에도 연결된다. PR 20220606의 success-rate/Latency 명칭 차이는 현재 제외 사례의 참고 사항으로만 남긴다. [설정](../configs/rca_preprocessing_proposal.json), [입력 조사](evidence/rca_input_inventory.json).

### Q07. 로그 연결과 부재 Pod 처리

- **미확인:** 실제 실험이 정확한 Pod 이름으로 로그를 연결했는지, 서비스/replica를 합쳤는지, 로그 없는 후보를 유지했는지 알 수 없다.

### Q19. 평가 공식·순위 기준·KPI·동점·실제 결과 연결

- **코드 관찰:** `LEMMA_Metrics.py`는 저장된 실행 결과 대신 고정 rank 목록을 집계한다. `rank < K`와 K개 PRK 평균을 사용한다. 양의1-based 단일 정답이면 `MAPK=mean(max(K-rank,0)/K)`이고 일반적인 AP와 다르다. 고정 [2,7]을 넣으면 표4 숫자가 나오는 것은 산술 확인이지 실행 재현이 아니다.
- **현재 선택:** 공개 지표를 수정하지 않고 KPI 포함1-based rank에 적용했다. Pod 전용 rank/Hit@K는 별도 명칭으로 보여 주며 동점은 원래 열 순서다. 이번 PC/MATMCD는 KPI 포함5/6위, Pod만4/5위다.
- **질문/요청:** “표4의 RK는 KPI 포함입니까? 순위는0/1 중 어느 기준이고 Top-K 경계 `<`는 의도한 정의입니까? 정확한 MAP/PR/MRR 코드·동점/복수정답·사례 집계와 예측 파일→rank 목록 변환 코드를 제공해 주십시오.”
- **중요성/근거:** 동일한 예측도 점수 해석이 달라진다. [공식 평가](../official/matmcd/LEMMA_Metrics.py), [지표 분석](RCA_METRIC_ADAPTER.md), [실제 결과](RCA_ORACLE30_RESULT_REPORT_20260927.md).

## 5. 내부 대조용 자료 묶음

다음5묶음은 전체 미확정 사항을 관리하기 위한 내부 분류다. 현재 문의에는 사용자가 선택한 [최종5개 질문](AUTHOR_INQUIRY_RCA_SHORT.md)만 포함한다. 설명 대신 해당 코드·설정으로 답할 수 있게 하되, 선택된 의문점은 직접 질문한다.

1. **표4의 최종 입력 묶음:** 날짜·장애 ID·CSV·Pod/KPI 매핑·정답·로그 대응·revision/hash. Q01~Q08.
2. **최종 CSV 생성 코드:** 시간 정렬·메트릭 융합·EVT와 후보 필터 설정. 특히 Q02~Q05.
3. **표4 실제 실행 버전:** command/config/commit 및 그래프 방향·첫 질문 캐시·로그/RAG 연결을 확인할 대표 prompt. Q09·Q14~Q17·Q20.
4. **실제 RAG/LLM artifact:** Pod 요약·검색 결과·최종 node_information·단계별 모델/추론/실패 정책. Q10~Q13. 웹은 사용했을 때만 Q22.
5. **실제 평가 자료와 환경:** rank 파일·GT·seed·반복/집계·지표 코드·환경 export. Q06·Q18·Q19·Q21. RE는 필요할 때 Q23.
