## D03: 근거로 확인한 동작

### 행렬의 용도를 구분해야 한다

| 대상 | 공식 코드의 의미 | 처리 |
|---|---|---|
| PC 결과 인과 그래프 `A[i,j]=1` | j → i. 행은 결과, 열은 원인 | cg2matrix·matrix_to_text와 일치. 전치하지 않음 |
| LLM 제약 `C[i,j]=1` | i → j를 요구. 행은 원인, 열은 결과 | matrix2backgroundknowledge와 일치. 전치하지 않음 |
| RWR | KPI에서 행을 따라 상류 원인 후보를 방문 | 역방향 탐색이라는 이유로 그래프를 뒤집지 않음 |

위 둘은 용도가 다른 행렬이다. 같은 인덱스 의미로 일괄 통일하면 기존 PC 제약과 RWR 동작을 바꾼다. 실제 fitting 없이 인공 A→B 그래프와 제약 한 개로 변환·표현·제약 입력 방향을 확인했다.

### 실제 불일치 3개

1. `ConstrainAgent/LLMs.py:155-181`: DomainKnowledgeLLM은 비영 원소를 모두 i→j라고 설명한다. 인공 A→B 그래프가 LLM 프롬프트에서는 B가 A의 원인으로 표현된다. -1(무방향)/2(양방향 표시)도 구별하지 않고 양쪽 원인 문장으로 만든다. 특정 질문의 직접 영향 확인도 `A[cause,result]`를 조회한다.
2. `LLMs.py:220-224`: 그래프 설명을 한 번만 생성한다. 그 안의 첫 (A,B) 쌍 직접 영향 문장이 이후 (B,Latency) 질문에도 그대로 남는다. 전체 그래프를 설명하는 공통 문맥과 질문별 문장을 구분해야 한다.
3. `LEMMA_experiment.py:72`: 외부정보 없는 첫 CC 보정 그래프를 생성하고도 RWR에는 초기 그래프를 다시 넣는다. 다만 **로그/추가정보가 연결될 MATMCD와 MATMCD-RE 단계는 이미 보정 그래프를 사용**한다(:131/:178). 이 오류 때문에 모든 최종 MATMCD 순위가 초기 그래프에서 나오는 것은 아니다. 같은 그래프도 서로 다른 난수 상태에서 RWR를 돌리므로 출력 순위가 반드시 같다고 단정하지 않는다.

논문 Algorithm 1은 각 변수 쌍에 대한 설명을 만들고 마지막에 보정 그래프를 출력한다. §4.3은 각 방법이 만든 그래프에 RWR를 적용한다고 설명한다. 하지만 어느 프롬프트 구현으로 표 4를 만들었는지는 공개 자료로 판별되지 않는다.

## D03: 2026-09-26 A안 승인

**채택 A — 공개 코드 동작 보존.** 사용자가 명시적으로 선택했다. 확인 가능한 공개 동작을 기준으로 삼고 위 불일치를 모두 공개한다. 이 경우 '공개 코드 기반 로컬 재현'이며 저자의 실제 실행 동일성은 미확인이다. 개선안 비교에서 오류 교정의 효과와 새 RCA 방법의 효과를 섞어 보고하면 안 된다.

**B — 미채택 대안: 논문 설명에 맞춘 별도 교정 프로필.** 원본 파일은 보존하고 로컬 어댑터에서 다음만 변경하는 안이다. 구현·적용하지 않았다.

- 그래프 `A[i,j]=1`의 문장을 j→i로 만들고, -1/2를 각각 무방향/양방향 표기로 명시하여 일방향 원인으로 단정하지 않는다. 질문의 직접 영향 조회도 결과행·원인열로 맞춘다.
- 쌍별 직접 영향 문장을 현재 질문의 (cause,result)로 생성한다. 과거 쌍 문장을 재사용하지 않는다.
- 외부정보 없는 첫 CC 단계의 RWR 입력만 해당 보정 그래프로 바꾼다. MATMCD/RE의 이미 보정 그래프를 쓰는 경로는 유지한다.

B는 LLM에 들어가는 내용과 일부 단계의 순위를 바꾸므로 결과 영향이 있을 수 있다. 저자가 실제로 사용한 구현이라는 근거는 없으며 '명시적 교정 기준선'으로 표시해야 한다. 비교하는 기준선/개선안에는 동일한 교정 방침을 적용하고 원본 코드 결과와 섞지 않는다. 성능 상승을 보장하지 않는다.

**현재 상태: A안 확정, 과학적 교정 미적용.** [승인 프로필](../configs/rca_protocol.json)과 rank_stage_with_original_rwr에 초기/초기/보정/보정 입력을 명시했다. 공식 프롬프트와 소스는 보존한다. [저자 문의 준비 문서](AUTHOR_QUESTIONS_D03_D04.md)에 문제별 근거·질문·미적용 조치를 따로 저장하고 TASK_018에 연결했다. 메일은 보내지 않았다.

## D04: 추가 추측 없이 확정한 공개 규칙

| 항목 | 확인한 규칙/근거 |
|---|---|
| RWR 기본값 | `steps=1000`, `rp=0.05`, `max_self=10`; 공개 4개 호출 모두 override 없음 |
| 시작점 | 입력 마지막 열. 현재 승인 CSV의 마지막 열은 Latency |
| RWR 내부 처리 | -1/2를 양방향 방문 가능하게 바꾸고 마지막 노드의 연결을 대칭화하는 원본 함수 그대로 |
| 정렬 | 방문 횟수 내림차순. 동점은 기존 입력 열 순서를 유지 |
| KPI 포함 | 공개 코드는 전체 labels를 정렬하며 Latency를 제거하지 않음 |
| 지표 | 기존 원문 PRK/MAPK/MRR 함수를 유지. `rank < K`를 임의로 `<=`로 교정하지 않음 |
| 순위 숫자 | 공개 표 4·고정 rank·MRR 대응은 1부터 시작하는 양의 순위와 일치 |

위 값은 **공개 코드에 확인되는 값**이며 저자 실행 당시 별도 override 부재를 입증한 것은 아니다.

표 4의 9개 방법에서 공개 rank 두 개를 넣었을 때 MAP@5, MAP@10, MRR가 모두 표의 표시 정밀도와 일치했다. MATMCD `[2,7]`은 30%/55%/0.32, RE `[3,6]`은 20%/55%/0.25다. 따라서 표준 AP 구현이나 `rank <= K`로 변경할 근거가 없다. 단, 공개 MAP@5는 rank 1 하나에도 0.8, rank 5에는 0이 되는 정의라는 점을 결과에 명시한다. 논문 부록 B.2의 표기 모호성은 표 4와 공개 계산을 기준으로 대조했으며 임의 수식 교정은 하지 않았다.

이는 **공개된 순위에 대한 산술 대조**다. 실제 실험으로 해당 순위·성능을 재현한 것이 아니다. 표 4의 두 rank(PR/CC)를 새 세 사례 결과의 평가값으로 재사용하지 않는다.

### 난수 재현 기록 모듈

[scripts/rca_ranking.py](../scripts/rca_ranking.py)는 고정 공식 RWR 함수와 공식 정렬 문장을 그대로 추출해 호출한다. 기본값/후보/동점 순서를 유지하며, 실행 직전·직후의 NumPy RNG 상태, 입력 그래프 해시, 전체 방문 횟수·순위와 공식 소스 해시를 반환한다. 새로운 실험 seed를 정하지 않는다.

인공 그래프에서 직접 원본 호출과 결과·난수 소비가 동일했고, JSON으로 저장한 RNG 상태를 복원하면 전체 결과가 일치했다. 검사에 쓴 seed 173은 작은 인공 검사 전용이며 실험 seed로 설정한 값이 아니다. 이 모듈에는 CLI나 실제 RCA 호출 연결이 없다. D03의 그래프 선택을 대신 결정하지 않는다.

이 방법은 고정 그래프의 RWR 재실행을 가능하게 한다. 저자의 미공개 seed를 복원하거나 LLM·전체 파이프라인의 결정성을 보장하지 않는다. 저자의 반복 횟수와 평균/최고값 선택은 미확인이다. 부록 B.1의 best-of-10은 Efficient-CDLMs 설명이며 MATMCD에 전용하지 않는다.

| 사례 | MATMCD 보조 코드 Ground_Truth | 현재 CSV에서의 대응 | 상태 |

정확 일치 prefix 검색은 **명시적으로 표시한 후보 연결 조사**다. MATMCD의 최종 정답 파일을 확보한 것이 아니며 D01 로그 연결을 prefix/서비스 단위로 변경한 것도 아니다. 2026-09-26 후속 지시에 따라 PR 유일 후보를 잠정 평가 노드로 사용하는 프로필을 구성했다. CC는 미확정 상태를 유지한다.

D03 승인과 함께 사용자가 제시한 방침대로 진행하도록 지시하여 다음을 적용했다. 같은 선택을 다시 묻지 않는다.

1. PR 두 사례는 공개 Ground_Truth의 유일한 pod 후보를 **공개 코드 기준 잠정 정답**으로 표시해 사용한다. 물리적 외부 원인과 그래프 안의 평가 노드가 다를 수 있음을 기록하고 저자에게 확인한다. reviews 등의 노드로 임의 교체하지 않는다.
2. CC는 두 pod의 예측 순위를 모두 보존하고 정확한 정답 확인 전 단일 MAP/MRR 값을 만들지 않는다. 두 후보 중 좋은 순위를 골라 점수를 높이지 않는다. 선택한 CC 실험 자체를 제외하는 조치도 아니다. 필요하면 두 가정의 진단값을 모두 표시하는 별도 안을 승인 후 적용할 수 있다.
3. 세 사례가 모두 평가 가능한 때 사례별 값을 먼저 보고하고 동일 비중의 3사례 집계를 로컬 프로토콜로 명시한다. 원논문 표 4의 두 rank 집계와 같다고 주장하지 않는다. CC 미확정 중에는 전체 3사례 집계값을 만들지 않는다. 현재 구현은 PR만의 부분 집계도 자동 생성하지 않고 개별 점수만 보존한다.
4. 방법·사례별 원본 단일 호출 구조와 RNG 상태 기록을 사용한다. 반복 실험/공통 seed 목록/평균·분산 보고는 이번 프로필에 추가하지 않는다. 'MATMCD가 best-of-10이었다'거나 Qwen의 seed 42가 RWR seed였다고 추정하지 않는다.

[rca_evaluation.py](../scripts/rca_evaluation.py)는 전체 순위를 받아 PR 잠정 점수와 CC 두 후보 순위를 반환한다. 원본 지표 함수·KPI·동점 순서를 유지하고 후보 누락·단계/프로필 혼합·부분 집계 요청을 거부한다. [승인 방침 인공 검사 23개 PASS](evidence/rca_approved_protocol_20260926T055338403913Z.json). 실제 예측 평가 결과가 아니며 전체 RCA 통합은 TASK_024다.

2026-09-26 적용 후 [원본 동작 재검사 40개도 PASS](evidence/rca_original_protocol_20260926T060140494272Z.json)했다. 공식 37개 파일·패키지·검사 시작 시점 설정을 보존했다. 현재 프로필과 준비 함수가 검증된 것이며 실제 RCA 준비 완료 판정은 아니다.

정답·평가 규칙은 결과를 보고 유리한 쪽으로 선택하지 않는다. 기존 시나리오 PPTX·정답 후보 조사 결과는 평가 전용으로 유지하고 LLM/RAG에 넣지 않는다. 근거 부족은 [TASK_018](../tasks/TASK_018_author_clarifications.md)에 일괄 문의 항목으로 유지하며 메일은 보내지 않았다.
