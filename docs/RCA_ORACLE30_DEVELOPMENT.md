## 사전에 고정한 조건

- `configs/rca_development_30.json`: 잠정 정답 Pod 1개와 다른 Pod 29개. 각 Pod의 기존 EVT 채널별 `positive_scores / aligned_rows` 최댓값 내림차순, 동률 Pod 이름순으로 29개를 선정한다. 로그 유무·RCA 결과·LLM 출력은 선정에 사용하지 않는다.
- 선정된 열은 원래 순서를 유지하며 Latency를 마지막에 둔다. 전체 51,529행과 모든 선정된 값은 동일하다. 전체 CSV를 같은 pandas 기본 옵션으로 읽은 뒤 열만 선택하고 NPY에 저장해 재직렬화에 따른 숫자 변화를 피한다.
- 공개 보조 코드의 잠정 정답은 `mongodb-v1-64c6b69879-p4wfp`. 최종 저자 정답 동일성은 미확인이다. 정답 메타데이터는 선정·사후 평가에만 사용하고 모델 프롬프트에는 정답 표시를 넣지 않는다.
- 선정은 첫 RCA 실행 전에 고정한다. 30개 후보 명세·데이터·프롬프트를 향후 개선안에도 동일하게 사용해야 한다. 성능을 보고 후보를 다시 고르지 않는다.

## 그대로 사용하는 구현

원본 PC/FisherZ, 로그 예시 선택, 로그 요약 프롬프트, RAG 분할·검색·합성, MATMCD 일반 모드의 모든 순서쌍, 제약 행렬, 보정 PC, RWR를 사용한다. 원본 소스·설치된 causal-learn은 수정하지 않는다. 승인된 D03 A의 공개 구현 문제도 유지한다.

30 Pod + KPI = 31노드이므로 930개 순서쌍 설명과 930개 제약 응답을 생성한다. 원래 전체 Pod용으로 준비한 로그 프롬프트를 그대로 보내지 않고, 공식 템플릿 전체를 검증해 `pod_list` 인자만 선정된 31열로 재생성한다. 내부 로그 텍스트·예시·온도는 동일하다. 누락 로그는 기존 D01 고정 부재 안내를 유지한다.

승인된 Qwen3.5-4B Q5_K_M non-thinking·81920 문맥·FP16·prompt cache ON, 출력 한도8192, BGE-M3 CPU FP32 배치1을 유지한다. 로그는 D07 승인으로 presence_penalty1.5, 설명은 후속 TASK_052 승인으로1.5, RAG 합성과 제약은0이다. [별도 변경 기록](RCA_DOMAIN_SAMPLING.md). API·RE·추가 모델·PC 최적화·자동 재시도·입력 자르기를 사용하지 않는다.

## 평가 해석

원본 RWR의 31노드 전체 순위·KPI 포함 원본 공개 지표를 보존한다. 추가로 KPI를 제외한 30 Pod에서 정답 순위, Hit@1/3/5, reciprocal rank를 개발 지표로 분리한다. 이는 한 사례의 한 실행이며 MRR 여러 사례 평균이나 통계적 유의성으로 해석하지 않는다. 원본의 입력 순서 동점 처리와 정답과 동점인 Pod 수를 함께 기록한다.

정답 포함으로 후보 누락 실패가 제거되므로 후보 선별 recall은 평가하지 않는다. 제외한 Pod가 인과 경로를 매개할 수 있어 전체 그래프와 결과는 달라질 수 있다. 이후 아이디어 비교에는 동일 후보·동일 입력·동일 모델·동일 평가를 사용하고, 반복 실행 및 기록된 RWR 난수 상태를 활용한 변동성 검토가 별도로 필요하다.

### 실행 계보와 이전 실패 이력

첫 실행 `20260926T132900237241Z`에서 원본 PC·RWR·평가가 691.12초에 완료됐다. 잠정 정답 Pod는30개 중4위(KPI 포함5위), Hit@5=1, reciprocal rank=0.25다. 로그20개와 RAG 생성1회도 정상 종료했다.
