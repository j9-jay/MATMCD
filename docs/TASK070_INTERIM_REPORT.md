# 중간 보고서: 추론 상태 기반 근거 검색 (TASK_070)

작성일: 2026-10-24 (2026-10-26 갱신: 0-1절 감사와 재실험) · 대상 기간: 2026-10-18 재계획 ~ 2026-10-26 · 저장소 `j9-jay/MATMCD`

## 0. 요약

- **연구 질문.** LLM이 인과 판단을 내릴 때, 하나의 질의로 근거를 한꺼번에 찾는 대신(flat RAG) **지금 추론에 필요한 단계(추론 상태)에 맞춰 근거를 골라 주면** 근거 품질과 최종 판단이 좋아지는가.
- **실험.** 장애 원인 분석(RCAEval RE2-OB, 30사례)을 주 시험대로, MATMCD 인과 발견 벤치마크 5종을 보조 시험대로 삼았다. 모든 방법은 같은 LLM·같은 근거 풀·같은 출력부를 쓰고 **근거 선택 방식만 다르다.** 방법과 평가 사례는 결과를 보기 전에 동결했다.
- **결과.** 계획한 평가는 모두 끝났다. **제안 방법(상태 동적)은 세 평가 모두에서 flat RAG보다 유의하게 낫지 않았다.**
  - 주 평가(출력부 B): Avg@5 0.848 vs 0.825 (p=0.76)
  - 카테고리 2: 평균 F1 0.472 vs 0.510
  - 보조 평가(출력부 A): Avg@5 0.510 vs 0.564 (p=0.15)
- **남은 신호.** 근거 품질 지표에서는 상태 기반 검색이 flat보다 1.5~1.7배 높았다. 다만 최종 순위 개선으로 이어지지 않았다. 계획기가 없는 단순 변형(역할 필터만, 상태 고정)이 제안 방법보다 높았고, 개발 사례에서의 큰 우위(0.94 vs 0.78)는 평가 사례에서 재현되지 않았다.
- **결정 필요.** 핵심 가설이 지지되지 않았으므로 논문 주장을 어떻게 세울지 정해야 한다(8절).

> **2026-10-27 갱신 (최종): RCA 실험 v1·v2는 무효다.** 사용자 계획서가 요구한 시스템 구조 문서가 근거 풀에 없었기 때문이다. Online Boutique 팀 위키로 근거 풀을 보완한 v3 재실험 결과는 아래 0-2절에 있다. 카테고리 2(인과 발견)는 위키 대상이 아니므로 0-1절의 v2 결과를 보조로 유지한다. 위 요약과 0-1절의 RCA 수치는 무효인 실험의 기록이다.

- **H1 (근거 품질): 지지.** 상태 기반 선택은 엄격 근거 정밀도 약 2배, 재현율 약 1.8배를 보였다. v1과 달리 LLM의 인용 정밀도도 높였다(0.28 대 0.21).
- **H2 (판단 개선): 지지되지 않음.** 순위 정확도의 flat 대비 차이는 30사례에서 유의하지 않다. 상태 고정과 역할 분리는 +0.06 안팎의 방향성만 보인다.
- **H3 (동적 계획 > 고정 규칙): 지지되지 않음.** 두 번의 독립적인 개발 모두에서 계획기를 쓰는 방법이 평가에서 떨어졌다. 4B 계획기의 선택이 일반화되지 않는다.
- **잡음 요인:** 판단 응답의 형식 실패(사례의 30%에서 하나 이상)가 방법 간 차이와 비슷한 크기의 잡음을 만든다. 형식 문제를 줄이는 것이 검출력 개선의 첫 과제다.
- **다시 하지 않은 것 (한계로 명시):** 출력부 A(보조 평가)는 같은 10사례 개발 문제를 안고 있다. MATMCD 카테고리 2 참고 기준선은 2개 데이터셋만 완료됐다.

## 1. 연구 개요와 취지

### 1.1 배경

- **MATMCD(다중 에이전트 인과 발견).** 데이터 보강 에이전트(DA-AGENT)가 웹·로그에서 정보를 모으고 요약하면, 인과 제약 에이전트(CC-AGENT)가 변수 쌍마다 인과 여부를 판단한다. 그 판단을 제약으로 넣어 통계적 인과 발견(PC)을 다시 돌린다. 이 구조는 결국 **"LLM 판단에 어떤 근거를 넣어 주는가"** 가 성능을 좌우하는 검색 증강(RAG) 문제다.
- **기존 RAG의 한계.** 보통 질문 하나로 근거를 한 번 검색한다. 그런데 인과 판단은 단계적 추론이다: 두 변수가 연결돼 있는가 → 원인 쪽에 이상이 있었는가 → 원인의 변화가 결과보다 먼저인가. flat 검색은 이 단계를 구분하지 않아서, "둘 다 이상했다" 같은 동시 발생 근거로 근거 예산을 채우기 쉽다.

### 1.2 아이디어 (사용자 제안)

**Reasoning-State-Aware Evidence Retrieval.** 추론 상태 분류(구조, 원인 이상, 시간 순서, 증상, 간접 경로 등)를 두고, 각 상태에 맞는 근거만 메타데이터로 걸러 상태별 질의로 검색한다. 계획기 LLM이 상황 개요를 보고 필요한 상태와 순서를 동적으로 고른다. 비어 있는 상태는 대체 상태로 넘어간다(근거 공백 처리). 근거 총량은 flat RAG와 같다.

### 1.3 목적과 범위

- **기여 범주는 NLP/RAG**(근거 검색·귀속)이며, 목표 학회는 ACL·EMNLP·NAACL·EACL·COLING이다. 장애 원인 분석과 인과 그래프 정확도는 **하류 지표**로만 쓴다. RCA 시스템이나 엔지니어링 기여로 범주가 넘어가지 않게 한다.
- **MATMCD의 위치.** 논문 구조(데이터 → 근거 수집 → 판단 → 제약 PC)는 빌려 쓰되, MATMCD 고유 아이디어(DA-AGENT 반복 검색·요약, CC-AGENT 2단계 판단)는 제안 방법에 넣지 않는다. MATMCD는 외부 참고 기준선이다.
- **핵심 비교는 제안 방법 vs flat RAG**이다. 나머지는 ablation 또는 참고값이다.

### 1.4 작업 가설 (R1 연구 질문은 미확정)

- **H1.** 상태 기반 검색은 flat RAG보다 원인 관련 근거를 더 많이 고른다(근거 정밀도·재현율).
- **H2.** 그 결과 하류 판단(원인 순위, 인과 그래프)이 flat RAG보다 좋아진다.
- **H3.** 동적 상태 계획은 고정 상태 순서보다 낫다.

### 3.2 근거 corpus (정답 미사용)

- **카테고리 1.** 사례마다 근거 단위 125~170개를 만든다.
  - 메트릭·KPI 이상 요약: 처음 5분 대비 |z|≥3인 분
  - 로그 템플릿별 분당 개수: 가변 값을 마스킹한 템플릿
  - trace 연산별 분당 건수·p90
  - trace 호출 그래프
  - 사례 ID는 불투명 ID로 바꾸고, 경로 누출 검사를 넣었다.
- **카테고리 2.** Serper 웹 검색 348회로 스냅샷을 만들어 고정했다.
  - 정답 네트워크를 설명하는 페이지(bnlearn 등)는 사전·사후 검사로 차단했다.
  - 데이터셋별 구간: AutoMPG 42, DWD 147, Sachs 230, Asia 183, Child 659.

### 3.3 비교 방법 (근거 선택만 다름)

| 방법 | 근거 선택 | 역할 |
|---|---|---|
| none | 근거 없음 | 참고 (LLM 지식만) |
| flat | 질의 하나로 BGE-M3 밀집 검색 상위 K개 | **핵심 기준선** |
| role_only | 상태 기반 방법과 같은 역할별 예산, 상태 없음 | ablation |
| state_fixed | 상태를 고정 순서로 사용 (계획기 없음) | ablation |
| **state_dynamic** | 계획기 LLM이 개요를 보고 상태와 순서를 고름, 근거 공백 시 대체 상태 | **제안 방법** |
| pc_only | LLM 없이 공식 PC 그래프만 | 참고 (출력부 A) |
| MATMCD | 공식 MATMCD 파이프라인 (로컬 모델로 대체) | 외부 참고 |

### 3.4 출력부 (판단 방식, 모든 방법 공통)

- **출력부 B (주, 사용자 결정).**
  - 사례 단위로 근거 24개를 고르고, LLM이 후보 서비스 12개 **전체 순위**를 근거 인용과 함께 출력한다.
  - 위치 편향을 줄이려고 후보 순서 3가지로 반복해 평균한다.
- **출력부 A (보조).**
  - 변수 쌍마다 근거 6개로 Yes/No를 판단한다.
  - Yes는 필수 간선, No는 금지 간선 제약으로 공식 PC에 넣는다.
  - 결과 그래프에 KPI에서 출발하는 RWR(seed 20회)을 돌려 원인 순위를 낸다.
  - 카테고리 2는 그래프 자체를 평가하므로 출력부 A를 쓴다.

### 3.5 지표

- **원인 순위.** RCAEval식 AC@k와 Avg@5, 역순위(RR). 동점은 무작위 순서의 기대값으로 채점한다. 후보 12개일 때 무작위 Avg@5는 0.25다.
- **근거 품질 (출력부 B).** silver 근거는 정답 서비스의 이상 구간이 있는 관측 단위다(평가에만 사용). 이에 대해 다음을 잰다.
  - 근거 정밀도와 재현율
  - 인용 정밀도: LLM이 인용한 근거 중 silver 비율
- **인과 그래프.** 공식 `Utils/metrics.py`의 Precision, F1, FPR, SHD, NHD.
- **통계.** 같은 사례 쌍으로 비교한다.
  - 부트스트랩 1만 회로 95% 신뢰구간
  - 부호 뒤집기 순열 검정 10만 회
  - seed 0
  - 카테고리 2는 데이터셋이 5개뿐이라 검정하지 않는다.

### 3.6 실행 환경과 고정 조건

- **LLM.** Qwen3.5-4B Q5_K_M (llama.cpp, non-thinking, 문맥 81,920, 단일 slot), temperature 0, seed 42.
- **임베딩.** BGE-M3 dense (CPU, FP32, batch 1).
- **공식 코드.** MATMCD 공식 코드는 고정 아카이브(commit ef2c3ec)와 바이트가 일치하는지 확인한 뒤에만 실행한다.
- **동결과 검증 장치.**
  - G1: 평가 30사례와 파일 CRC를 고정했다.
  - G2: 방법 설정과 스크립트 해시를 동결했다. 줄바꿈은 정규화해 비교한다.

  - 동결 이후의 변경은 amendments 파일에 사유와 해시로만 허용한다.
  - 평가 실행기는 시작 전에 이 검증을 통과해야 돌아간다.

## 6. 해석

### 6.1 가설별 판정

| 가설 | 판정 | 근거 |
|---|---|---|
| H1 근거 품질 향상 | **부분 지지** | 출력부 B에서 상태 기반 두 방법의 근거 정밀도(0.067~0.068 vs 0.040)와 재현율(0.187~0.202 vs 0.121)이 flat보다 높다. 단, 인용 정밀도는 state_dynamic이 flat보다 낮다(0.184 vs 0.214). LLM이 좋은 근거를 받아도 그것을 인용·활용하지는 않았다. |
| H2 하류 판단 향상 | **지지되지 않음** | 출력부 B는 차이 없음(p=0.76). 카테고리 2와 출력부 A는 flat이 오히려 앞선다. |
| H3 동적 > 고정 | **지지되지 않음** | 출력부 B와 카테고리 2에서 state_fixed가 state_dynamic보다 높다. 출력부 A만 반대(0.510 vs 0.454)이며 유의하지 않다. |

### 6.2 원인 후보 (확정 아님)

1. **개발 사례 과적합.** 상태 분류, 상태별 예산, 계획기 프롬프트를 개발 10사례로 두 차례 다듬었다(v1→v2, 출력부 B v1→v3). 개발 우위(+0.16)가 평가에서 +0.02로 줄어든 것은 전형적인 과적합 양상이다.
2. **표본 크기.** 30사례에서 Avg@5 차이의 신뢰구간 폭이 약 ±0.13이다. +0.05 수준의 효과는 이 설계로 검출할 수 없다.
3. **근거 품질과 판단의 단절.** 근거 정밀도가 올라도, 4B 모델이 근거 24개 중 무엇을 근거로 삼는지는 인용 정밀도에서 보듯 개선되지 않았다. 검색이 아니라 판단 모델 쪽이 병목일 수 있다.
4. **출력부 A의 증폭 구조.** 상태 방법은 원인 쪽 이상 근거를 항상 포함해 Yes가 늘어난다(63.9 vs 55.1). 공통 출력부는 Yes를 필수 간선으로 넣으므로 그래프 왜곡이 커진다. 개발 단계에서 세운 가설과 같은 방향의 관찰이다.
5. **단순한 구조 정보가 대부분의 이득을 설명.** role_only(역할별 예산만)가 출력부 B에서 가장 높다. 이득은 "구조 근거와 관측 근거를 나눠 넣는 것"에서 오고, 상태 계획 자체의 추가 기여는 보이지 않는다.
6. **카테고리 2 Sachs.** 웹 근거가 오히려 판단을 흐렸다(모든 근거 방법 < 근거 없음). 생화학 용어의 동음이의(예: DAG)나 일반론 문서가 섞인 영향일 수 있으나 확인하지 않았다.

### 6.3 MATMCD 비교에 대한 해석

- MATMCD는 카테고리 1에서 PC만보다 나았다. 하지만 카테고리 2의 완료된 두 데이터셋에서는 정보 없는 CC-agent보다 낫지 않았다.
- 이 환경(로컬 4B 모델, BGE-M3, 공식 코드 보정 3건)에서는 논문 표 1의 MATMCD 우위를 확인하지 못했다.
- MATMCD는 출력 경로가 달라서, 제안 방법과의 차이 원인을 특정할 수 없는 참고값으로만 해석한다.

## 7. 한계와 타당성 위협

- **모델.** 로컬 Qwen3.5-4B 하나만 썼다. 더 큰 모델에서는 근거 품질 이득이 판단으로 이어질 수 있으나 검증하지 않았다.

- **MATMCD 카테고리 2.** 2개 데이터셋만 완료했다. 공식 코드에 보정 3건이 필요했고, 누출 검사가 없다.
- **연구 질문 미확정.** 연구 질문(R1)과 지도교수 합의가 아직 없다. 여기 가설은 작업 가설이다.
