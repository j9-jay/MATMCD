## 큰 문맥의 메모리 추정과 한계

현재 서버 로그의 GPU 버퍼는 모델 2,987.56MiB, FP16 KV 512MiB, recurrent 50.25MiB, compute 20MiB다. 147,456은 현재 문맥의 9배이므로 같은 배치의 FP16 KV는 약 4,608MiB, 증가량은 4,096MiB로 추정된다. 모델/상태/compute를 더한 주요 버퍼만 약 7,665.81MiB다. 이 값에는 드라이버·다른 앱·추론 중 추가 workspace의 변동이 포함되지 않는다.

관측된 GPU 전체 사용 표본 최대 4,253MiB에 증가량만 단순 가산하면 8,349MiB로 물리 VRAM 8,192MiB를 넘는다. 이는 보수적인 산술 참고값이지 확대 설정의 실제 할당 결과가 아니다. 초기 nvidia-smi의 free와 서버 시작 중 CUDA 조회 free(7,103MiB)는 시점과 런타임 예약 범위가 달라 동일값으로 취급하지 않는다. 종료 로그의 unaccounted 1,114MiB를 모두 사용자 앱 점유라고 단정하지 않는다.

**147,456/all 또는 147,456/24는 이번에 구동하지 않았다. 따라서 확대 환경의 OOM 확정·성공 확정·응답 속도/품질 보장으로 해석하면 안 된다.** 이전 보고서의 부족 판단도 확대 실행의 실패 이력이 아닌 추정이었다.

Qwen 공식 모델 카드는 기본 문맥 262,144를 명시한다. 요구된 147,456은 이 범위 안이지만, 실제 긴 로그를 올바르게 요약하는 품질과 PC에서의 처리 속도는 별도 검증이 필요하다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-4B).

## 별도로 유의할 점

- 단순히 32,768로 늘려도 42개, 131,072에서도 3개 입력이 기존 출력 한도까지 들어가지 않는다. 139,264는 현재 최대 필요량보다 68토큰만 많아 이후 RAG/그래프 길이를 위한 여유를 보장하지 못한다. GPU 여유도 작아 우선안으로 권장하지 않는다.
- RAM 증설이나 WSL memory 조정만으로 GPU 전체 배치의 VRAM이 늘어나지는 않는다. WSL 기본 memory 한도는 호스트 RAM의 50%이며 설정 변경은 별도 환경 변경이다. 현재 설정은 유지했다. [Microsoft WSL 설정](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).
- 더 작은 모델, 로그 잘라내기, 분할 요약, Pod 제외는 모델·근거·요약 방식에 새 차이를 추가한다. 기존 조건을 보존하는 후보를 먼저 검토한다.
- 문맥 문제를 해결해도 현재 공개 루프의 세 단계 방향쌍 호출 831,396회와 로그 요약 426회·RAG는 남는다. CPU 분산으로 구동된다는 사실만으로 전체 실험이 현실적인 시간에 끝난다고 보장할 수 없다. [호출 규모](LOCAL_RCA_RUNTIME.md).
