# TASK_035 - 누락 pod 로그의 처리 정책

## 목적
metric 후보를 유지하면서 로그가 없는 노드의 추가 정보를 어떻게 다룰지 결정한다.

## 작업 항목
- [x] 실제 로그 쌍과 누락 수 조사 및 존재하는 파일 연결
- [x] 완전 자료 확보 / 부재 명시 / 후보 제외의 영향·구체안 작성
- [x] 사용자 선택 확인 — 2026-09-25, 로그 쌍 불일치를 유지하고 진행
- [x] 승인한 정책만 구현하고 출력·전달 형식 및 누락 기록 검증 — 실제 5개 사례·오프라인 44개 검사 PASS

## 확인 사항
기존 metric 후보를 제거하지 않았다. 누락은 PR 99/95/64/80개와 CC 72개다. 유사 이름 매핑·빈 로그·가짜 사건 생성은 미적용이다.

TASK_037에서 사용자가 제기한 파싱 오류 가능성을 재검증했다. 로컬 경로/이름 매칭에서 놓친 파일은 발견되지 않았고 공개 metric/log 범위 차이를 확인했다. CC 원시 노드 로그에는 누락 pod 3개의 관련 언급이 있어 '원시 자료 어디에도 정보가 없음'을 뜻하지 않는다. [원인 분석](../docs/D01_LOG_COVERAGE_ANALYSIS.md). 이후 사용자가 B안으로 진행을 승인했다. 이는 누락 원인 해결/확정과 별개다. MATMCD의 최종 후보/대응 정책은 별도 확인한다. 재시작·종료를 원인으로 추정하여 모델 입력에 넣지 않는다.

## 결과
[RCA_DECISIONS.md D01](../docs/RCA_DECISIONS.md#d01-로그가-없는-pod에-어떤-정보를-제공할-것인가)에 근거·선택지·권장 B안의 정확한 표시와 영향, 승인 범위를 작성했다. 입력 파일 준비 TASK_032와 정책 선택을 구분한다.

2026-09-25 사용자가 로그 쌍 불일치를 유지한 채 진행하도록 결정했다. [승인 설정](../configs/rca_log_policy.json), [부재 처리 어댑터](../scripts/rca_log_evidence.py), [오프라인 검사](../scripts/check_rca_log_evidence.py)를 구성했다. 후보 1,057개(정확한 쌍 647개/부재 410개)와 별도 KPI 5개를 유지하는 근거 manifest 5개를 외부 processed_data/lemma_rca_log_evidence_v1에 준비하고 inputs.json으로 연결했다.

[검증 증거](../docs/evidence/rca_log_policy_20260925T123410900857Z.json): 오프라인 44개 검사 PASS. CSV 5개·전처리 manifest는 기존 SHA256과 일치, 공식 37개 파일은 ZIP과 바이트 동일, 입력/로그 연결 경로와 후보/순서 보존. 없는 pod/KPI에는 요약 콜백을 호출하지 않았고 부재 덮기·부분 쌍·알려진 파일 소실·읽기 실패를 오류로 구분했다. 인공 콜백만 사용했으며 LLM/실제 로그 CSV 파싱/RCA는 실행하지 않았다.

[정책 명세와 한계](../docs/RCA_LOG_POLICY.md). D01의 정책·어댑터 준비가 DONE이며 실제 요약/RAG/모델의 통합은 TASK_024다. 후속 D02 원본 전체 읽기의 대표 검증은 TASK_036에서 별도 승인·완료했다. 원래 누락된 파일을 복구하거나 재시작 원인을 확인한 것으로 취급하지 않는다.

TASK_039 후속: 현재 세 사례만 선택하도록 실행 범위를 좁혔다. D01 정책 자체는 동일하며 활성 후보 642개·정확한 쌍 426개·부재 216개·KPI 3개다. [현재 범위 검사 33개 PASS](../docs/evidence/rca_log_policy_20260925T125049357248Z.json). 위 5개/44개 검증은 과거 준비 이력으로 유지한다.
